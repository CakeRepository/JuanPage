# M1 Meaning Protocol 1.0

M1 is JuanPager's machine-native transport. It moves identity, facts, relationships, actions, evidence, uncertainty, and authority without requiring an agent to describe a user interface or use human-language property names.

M1 is **not** a second renderer. Every valid packet materializes into JuanPage 1.0 and is rendered by the single trusted JuanPager runtime.

## Design invariants

1. Tuple positions and numeric opcodes are the wire contract.
2. Symbols are stable opaque identifiers. Vocabulary is a replaceable human projection.
3. Untrusted HTML, CSS, JavaScript, and component code are never transported.
4. Permission policy is enforced before actions reach the renderer.
5. Every state transition carries a base revision and next revision.
6. Executable actions carry an idempotency key and produce receipts.
7. Latent vectors may be added as hints, but never as execution or permission authority.

## Packet

```text
[1, packetId, revision, vocabularyId, vocabulary, records]
```

- `packetId`: stable symbol identifying the shared world.
- `revision`: non-negative monotonic integer.
- `vocabularyId`: optional vocabulary identity.
- `vocabulary`: `[symbol, localizedText][]`.
- `records`: opcode tuples.

## Records

### 0 Header

```text
[0, titleText, intentText?, descriptionText?, theme, requestedLens, groupBy, density]
```

### 1 Entity

```text
[1, entityId, typeSymbol, nameText, groupText?, statusText?, tone, summaryText?, actionIds[], tags[]]
```

### 2 Fact

```text
[2, entityId, propertySymbol, value, labelText?, format, display, currency?]
```

### 3 Relation

```text
[3, fromEntityId, toEntityId, relationSymbol, labelText?]
```

### 4 Action

```text
[4, actionId, actionKind, labelText, target, fieldOrUrl, config, tone, descriptionText?, operationSymbol?]
```

Action kinds:

| Code | Meaning | Config |
|---:|---|---|
| 0 | toggle | initial boolean |
| 1 | number | `[initial,min,max,step]` |
| 2 | choice | `[initial, [[labelText,value],...]]` |
| 3 | text | `[initial,placeholderText,multiline]` |
| 4 | open | URL in `fieldOrUrl` |
| 5 | copy | `[sourceCode,target?,field?]` |
| 6 | emit | object IDs |

### 5 Metric

Reserved for canonical computed metrics.

### 6 Signal

```text
[6, signalId, targetId, severity, reasonText, confidence, sourceText?, observedAt?]
```

### 7 Evidence

```text
[7, evidenceId, targetId, sourceText, claimText, confidence, observedAt?]
```

### 8 Permission

```text
[8, actionId, policy, reasonText?]
```

Policies: `0 allow`, `1 deny`, `2 human approval required`.

Denied actions are removed before rendering. Approval-required actions are projected as proposals and cannot mutate state directly.

## Deltas

```text
[1, packetId, baseRevision, nextRevision, mutations]
```

Fact mutations:

```text
[20, entityId, propertySymbol, value]   // set
[21, entityId, propertySymbol]          // remove
```

Action mutations:

```text
[30..34, mutationId, actorId, actionId, targetId?, arguments, idempotencyKey, timestamp]
```

| Code | Meaning |
|---:|---|
| 30 | invoke action |
| 31 | propose action |
| 32 | approve action |
| 33 | reject action |
| 34 | cancel action |
| 35 | action result |
| 36 | action failure |

## Receipts

```text
[1, receiptId, packetId, actionId, mutationId, state, timestamp, idempotencyKey, actorId, evidenceIds, result]
```

Receipt states: proposed, authorized, executing, succeeded, failed, rejected, cancelled.

A receiver must treat `(packetId, idempotencyKey)` as replay-safe. Re-sending the same authorized request must not execute it twice.

## Capability negotiation

```text
[1, locale, inputMask, lensMask, operationSymbols, width, height, reducedMotion]
```

The renderer may hide unsupported operations, select another supported lens, and use compact density on constrained surfaces. Capability negotiation never grants permission.

## Security profile

Informational packets may be unsigned. Any adapter that connects M1 to external execution should additionally verify issuer, audience, expiration, digest, and signature before accepting action mutations. Signature envelopes are deliberately transport-level so the canonical semantic tuples remain stable.
