# M1 Meaning Protocol 2.0

M1 is JuanPager's machine-native semantic transport. It moves identity, facts, relationships, possible operations, data projections, evidence, uncertainty, and authority without requiring an agent to author a screen or component tree.

Every valid packet materializes into JuanPage 2.0 and is rendered by the single trusted `renderPage` runtime.

## Design invariants

1. Tuple positions and numeric opcodes are the wire contract.
2. Symbols are stable opaque identifiers. Vocabulary is a replaceable human projection.
3. M1 transports meaning, not HTML, CSS, JavaScript, components, or layouts.
4. Information is inert unless an affordance and binding make it interactive.
5. Permission policy is enforced before an affordance reaches the renderer.
6. Fact edits, scope changes, selections, and external operations are distinct mutations.
7. Every state transition carries a base revision and next revision.
8. External operations carry an idempotency key and produce receipts.
9. Capability negotiation may remove interaction but never grants authority.

## Packet

```text
[1, packetId, revision, vocabularyId, vocabulary, records]
```

- `packetId`: stable symbol identifying the shared world.
- `revision`: non-negative monotonic integer.
- `vocabularyId`: optional vocabulary identity.
- `vocabulary`: `[symbol, localizedText][]`.
- `records`: opcode tuples.

## Records

### 0 Header

```text
[0, titleText, intentText?, descriptionText?, theme, legacyLayoutHint?, legacyGroupHint?, legacyDensityHint?]
```

Layout hints are ignored by JuanPage 2. The runtime composes the human surface from semantic content, bindings, host dimensions, and input capabilities.

### 1 Entity

```text
[1, entityId, typeSymbol, nameText, groupText?, statusText?, tone, summaryText?, affordanceIds[], tags[]]
```

The `affordanceIds` list provides default ownership only. It does not create a component or button. Materialization converts ownership into explicit JuanPage bindings.

### 2 Fact

```text
[2, entityId, propertySymbol, value, labelText?, format, display, currency?]
```

### 3 Relation

```text
[3, fromEntityId, toEntityId, relationSymbol, labelText?]
```

### 4 Affordance

```text
[4, affordanceId, affordanceKind, labelText, target, fieldOrScopeOrUrl, config, tone, descriptionText?, operationSymbol?]
```

| Code | Semantic effect | Config |
|---:|---|---|
| 0 | set Boolean fact | initial Boolean |
| 1 | set numeric fact | `[initial,min,max,step,presentation?]` |
| 2 | set choice fact | `[initial, [[labelText,value],...]]` |
| 3 | set text fact | `[initial,placeholderText,multiline]` |
| 4 | navigate | URL in `fieldOrScopeOrUrl` |
| 5 | copy | `[sourceCode,target?,field?]` |
| 6 | invoke external operation | included object IDs |
| 7 | set page scope | `[initial, [[labelText,value],...], scopedField]` |
| 8 | select semantic targets | `["single"|"multiple"]` |
| 9 | inspect semantic target | none |

A single affordance may be bound to multiple targets or presentations. For example, one period-scope affordance can appear as both a select control and interactive projection data points.

### 5 Projection

```text
[5, projectionId, labelText, sourceType?, dimensionField, measureField?, operation, format, currency?, affordanceId?, ignoreScopeIds?]
```

Operations:

| Code | Meaning |
|---:|---|
| 0 | count objects by dimension |
| 1 | sum measure by dimension |
| 2 | average measure by dimension |

A projection describes data semantics, not a chart component. The runtime may present it as bars, rows, a compact summary, voice output, or another accessible representation. If `affordanceId` is provided, each projected datum may activate that semantic affordance with the datum key as its value.

### 6 Signal

```text
[6, signalId, targetId, severity, reasonText, confidence, sourceText?, observedAt?]
```

### 7 Evidence

```text
[7, evidenceId, targetId, sourceText, claimText, confidence, observedAt?]
```

### 8 Permission

```text
[8, affordanceId, policy, reasonText?]
```

Policies: `0 allow`, `1 deny`, `2 human approval required`.

Denied affordances and their bindings are removed before rendering. Approval-required operations materialize as `invoke` affordances with approval policy; they cannot directly mutate facts.

## Deltas

```text
[1, packetId, baseRevision, nextRevision, mutations]
```

### Fact mutations

```text
[20, entityId, propertySymbol, value]   // set fact
[21, entityId, propertySymbol]          // remove fact
```

### Scope mutations

```text
[22, scopeId, value]                    // set view scope
[23, scopeId]                           // clear view scope
```

A scope changes the human and agent viewing context. It does not rewrite a domain fact.

### Selection mutations

```text
[24, selectionId, targetIds[]]          // replace semantic selection
```

### External operation mutations

```text
[30..34, mutationId, actorId, affordanceId, targetId?, arguments, idempotencyKey, timestamp]
```

| Code | Meaning |
|---:|---|
| 30 | invoke operation |
| 31 | propose operation |
| 32 | approve operation |
| 33 | reject operation |
| 34 | cancel operation |
| 35 | operation result |
| 36 | operation failure |

Operation arguments should include relevant scope and selection context when execution depends on what the human was viewing or selecting.

## Receipts

```text
[1, receiptId, packetId, affordanceId, mutationId, state, timestamp, idempotencyKey, actorId, evidenceIds, result]
```

Receipt states: proposed, authorized, executing, succeeded, failed, rejected, cancelled.

A receiver must treat `(packetId, idempotencyKey)` as replay-safe. Re-sending the same authorized request must not execute it twice.

## Capability negotiation

```text
[1, locale, inputMask, legacyLensMask, operationSymbols, width, height, reducedMotion]
```

`legacyLensMask` remains reserved in the M1 tuple but does not select a JuanPage 2 layout. The renderer uses width, height, input support, locale, and reduced-motion preference to compose an appropriate surface.

Unsupported external operations are removed. Unsupported interaction must never be rendered as an inert imitation.

## Trust projection

Unsigned or otherwise unverified packets may retain safe local affordances:

- inspect;
- set local facts;
- scope;
- select;
- copy safe information.

External invocation and navigation are removed unless the host establishes the required trust and authority.

## Security profile

Any adapter that connects M1 to external execution must verify issuer, audience, expiration, nonce, digest, signature, delegation, permission, revision, and idempotency before accepting an operation mutation.

Display text, vocabulary labels, embeddings, and latent vectors never grant identity, permission, signature, or execution authority.
